# 固定执行流程：按1→2→3→4→5执行

开始、续接或收到新决定，先做步骤1—2；沿本批主线新项、返工分支及已授权独立后继，连续完成方法校准、实现、页面操作、取证、自检、普通修正与收尾。单个结果完成、失败或受阻后继续其它项，不逐条交回领下一步；本批授权项结算后做步骤5，并衔接后继或明确下一批清单ID。小任务简记，复杂任务更新原清单与回执，不为每步创建文档。

## 多轮目标的清单与推进硬规则

1. **按总清单执行。** 需要多轮的总目标在首次决策时就必须有可分别验收的表格或编号列表，包含稳定ID、完成条件、状态、依赖及结果/证据入口；分支也应有子清单。读取并复用该清单，核本批主线新项、返工项及后继ID。缺清单时按既有明确目标/原验收项补齐必要列项；范围或验收未定只停依赖动作，不能连续多轮无总清单执行。
2. **每轮显示总体与分支进度。** 开始、交回时明报“总项数N｜已验收C｜未完成N−C”，未完成按待执行、执行中、待复审、未通过、阻塞等互斥状态列清；另报本轮首次执行、返工、提交验收、复审确认完成及下一批的ID/数量。尚未执行与总未完成分开，逐项状态和总数对齐，不重复统计父子项。执行完成待复审不擅自改为已验收。
3. **每个循环有新增执行或新增验收。** 总目标未完成且非全局阻塞时，必须推进尚未执行的主线或分支项，或取得新增验收完成项；可乱序、可分批。已授权的独立新项继续做，不能只围绕上一轮失败反复修正/核证而空置主线。首次实际执行才算新执行项；重命名重试、拆命令、补报告不算。不能保证通过时如实记录失败，同时继续其余项，不伪造进度。
4. **分支并行，不吞掉主线。** 多轮分支首次出现即按原任务范围列子项、总数、已验收、未完成和依赖，与其它授权项并行推进。未通过项本轮未选中仍保留；修复分支通过不自动关闭主线原验收项，不重复增加主线完成数。并行不扩张代理、聊天、交易、资源或发布授权。
5. **局部停止，总体继续。** 方法失效、到界或待决只阻塞对应项，立即继续其它已授权项。只有总清单及全部分支确无可执行独立项，才能暂缓总体推进；列全部剩余项的阻塞事实、解除条件和责任方。若本批做完而清单还有可执行但未派发的新项，交回这些ID供Supervisor同轮续发，不能当作全局阻塞。用户明确暂停或限制整体授权时遵用户指令。

## 强制明文输出协议：未输出就不得过门禁

**MUST向用户可见消息明文输出每个核心步骤的结果与门禁，不能只默默执行、只写AGENTS/JSON、只说“已检查”，或到最后补写此前通过。** 取得必要事实后、进入依赖它的下一核心步骤前输出；无需新事实的连续步骤可在同一条消息按序列出，原授权内不增加审批或交回。步骤3—4内普通修正连续做，只在进入验证或新事实改变门禁时更新，不为每个命令重复开工报告。只输出结论、事实与边界，不输出内部推理或凭据。

每步用这个格式，四项缺一即未完成：

> 【步骤N｜步骤名】结果：具体结论。门禁：PASS / BLOCKED / FAIL / UNKNOWN / NOT RUN。依据：原条款或文件位置、实际事实与必要时点。下一动作：可继续什么；受阻动作停在哪里。

| 核心步骤 | 必须明文输出的结果 | 关键门禁：进入下一步前必须成立 |
| --- | --- | --- |
| 1 读取任务 | 总清单/分支进度、本批新项与返工ID、原约定步骤/判据、原授权后继 | 多轮目标已有可分别验收的总清单；行为与判据明确，不逐条交回。 |
| 2 核执行前提 | 实际运行对象/版本、资源归属、复用原件、方法/取证能力、累计预算 | 依赖前提有事实；必要正常交互及关键时点取证可行；未知/失败时禁止依赖外部动作。已到界或同失败无新事实不再校准。 |
| 3 自主执行 | 实际修改/操作、清单ID/状态、本轮新执行与返工数量、累计投入 | 连续完成本批与独立后继，局部受阻转其它项；辅助材料和重命名重试不算新执行。 |
| 4 验证结果 | 每个用户结果的原步骤、预期/实际、直接原件、未达分类和必要回归 | 正常入口、反馈/自动更新、业务结果和收尾等已知条件均对照；部分通过不整项PASS，缺件不伪报。 |
| 5 收尾交回 | 总数/已验收/未完成分项、本轮增量、分支、对象终态、成本与下一批ID | 已知遗漏先补；独立授权项继续；无新增验收如实记0，但不能仅报0而省略新执行与后继。 |

**硬性判定**：没有输出、依据空泛、必要事实UNKNOWN/NOT RUN、必要前提BLOCKED/FAIL，均不得把相应门禁写PASS或继续依赖动作。允许继续的独立项明写不受该门禁影响的事实；校准PASS、接口PASS、映射PASS不能冒充用户结果PASS。开工输出步骤1—2，进入业务执行/验证时输出步骤3—4，交回输出步骤5；真实新事实改变门禁立即更新。不能为了输出格式停止普通连续执行或索要新批准。

## 1. 读取当前任务

MUST在调查/修改/测试前完整读当前项目指定的交接文档（未指定时用AGENTS.md）及其当前必要执行方案；按项目要求读适用skill。用户当前指令优先于旧任务，旧路书退出；不从其他项目找任务，不要求用户复制Prompt或重复授权。
**必须核出的结果：任务要点**——单元ID/任务修订、产出、对象与输入、具体步骤/已定规则、前提与边界、逐条验收与原件/采集时点、停止/升级条件。核清每条条件对应哪个动作和观察，特别是正常页面使用、自动更新、外部结果和收尾。直接使用原任务/回执表，普通小修不另交开工报告。
最小验收单元是完整用户结果，不是最小派发包；输入/保存、操作、业务反馈/自动更新、结果核对和收尾属于同一结果的验收条件，不能把每个条件变成一次交回。同批多个单元分别完成与结算，共用运行不等于共用PASS。完整读取共享目标有助理解任务，但不重新做全局排序或承担任务之外的设计。实现细节自主决定；关键输入、业务规则、验收步骤或允许测法缺失/冲突时列明具体缺项，只停依赖项，不猜测隐含标准。
文件缺失时沿用户明确任务，仅澄清会实质改变行为或授权的缺项。复用原验收项建立缺失清单，在原范围内细化执行分支并回填进度，不另改总体范围、优先级或验收标准；任务未附选题理由或工期推导，不构成缺项。
STOP IF对象/输入无法合法确定、业务规则/验收冲突、必要授权缺失：写清具体缺项交回待决，只停相关动作；其它明确独立项继续。

## 2. 核执行前提与既有对象

MUST用当前代码、配置及任务指定原件核实际输入、环境/运行版本、资源所有权、必要前提和可复用结果；有CodeGraph按项目规则先用。只查本任务相关事实，不重新扫全项目或自行定系统门禁。
**必须记下的结果：前提核对**——实际对象/输入与版本、可用资源/前提、复用哪些结果、已有累计投入/次数，以及确实阻塞的缺项。归属不明对象保护，不默认停服务、注销、重启、重下单或新建资源。
父项NOT RUN/FAIL不等于未执行。若发现任务与已完成事实直接重复，检查任务注明的实际变化/必要缺字段；用户明确重测按其要求，其它重复缺这类信息时暂停重复动作，交回原结果与具体冲突，不自行安排重测或补写选题理由。
昂贵调查或停滞返工缺累计边界时交回缺项；普通明确小修不索要预算文书。日期、会话、HEAD、换工具不清零，也不是自动重跑理由。
关键前提不成立或方法无法支持指定结论，按清单ID记录具体阻塞并转向独立项，不猜业务规则、改验收、扩范围或造框架。收到仅重述同一失败前提的续接，不重做该路径校准或整理，继续本批其它新项和分支；已证可行路径直接完成原完整链，不为普通步骤再要任务。全部剩余项确受阻才报告全局阻塞。
在昂贵批量执行/外部副作用前，先校准一个完整代表链路的正常操作、观测、断言和必要原件。UI任务先用无交易点击/键盘确认页面可操作；只有改变样式、时钟、强制事件或截图推动才能成功，不能当普通用户可用。允许的只读取证辅助与实际用户动作分开记，方法失败就BLOCKED，不先发交易再补方法。关键期初/期末或在途原件能力先核，采集发生在指定时点；校准不扩成新工具工程。

## 3. 自主实现与调试

先核真实输入、配置和必要调用链，按已定行为实现；明确根因与改法直接最小修正。仅未知故障才追第一个错误转换、提出一个假设并做可支持/否定它的区分观察，不试探性堆补丁，不给普通实现强造故障诊断步骤。
按单元连续完成“实现/操作 → 自检 → 明确缺陷修正 → 关联回归 → 收尾”，不为编译、选择器或普通装配修正逐次交回。修布局/重构时先保留任务要求的原有编辑与操作能力；新增阈值/时效检查须核它依赖的数据更新机制，不能仅拒绝过期输入却使正常业务入口不可用。
按已定行为完成范围内实现、明确缺陷修正与必要回归，自主选择算法实现、代码组织、命令和测试方法。语义明确的普通数据结构与参数选择不升级；未定产品规则、核心模型/所有者、公共契约、兼容性或跨系统职责选择才交回。
按任务规定处理必须修和可保留项。发现问题不自动授权扩范围、造工具或补历史；不追求完美代码或穷举排列。未纳入任务的缩放、换行、动效、罕见组合等外围发现登记Remaining，不扩成整轮修复；实际遮蔽关键数据、误导金额/方向或阻断操作，提交反例并按现有安全边界处理，不自行展开全矩阵。
低成本测试/工具装配错误可自主修正；工具修复受同一任务预算和范围约束，不能自发增加框架、预检阶段或额外交付。超边界或持续无新判别事实，停止该方法并报告未验证。
只串行真实代码、数据、资源所有权、运行状态或用户前提。共同环境污染时隔离或顺序执行；同文件、同报告、同阶段或局部失败不冻结独立项。达到既定条件即推进已授权续接，真正需裁决的步骤等待。
**必须保留的结果：变更/执行事实**——对应清单ID、首次执行/返工、实际修改或动作、结果状态及累计投入；未知故障另记假设及区分结果。只换关键词、脚本或相同输入不算新执行或验收进展。
边做边回填原任务条款，不等最后凭记忆补齐。参数对照保留输入/提交值和策略结果，注明固定项与改变项；会互相混淆的变化不能声称独立因果。任务要求的通知、实时反馈、停止或余额观察嵌在同一运行中，不能结束后遗忘再新发一轮。
发现实际执行超出任务、缺前提或不断新增完成条件，报告具体差异与已耗投入，交回待决。子代理只做有收益的独立工作，遵守会话限制，不机械多开任务。

## 4. 验证指定结果

验证用户原场景、受影响生命周期及必要回归。交易、账实、权限、停止/恢复、必要并发/延迟用对应业务事实证明；构建、HTTP 200和进程存活不能替代。
有页面行为变更时，在实际受验产物上从用户入口走受影响的完整操作；受控组件/测试替身可辅助定位，但不能单独替代页面可用结论。源码HEAD、候选测试与当前服务分开，不把未部署修复报成现场可用；启停遵任务授权与对象所有权。
按主要机制与真实风险验证，不穷举理论排列。每项新增测试/采集只支持当前必要结论；已有必要检查通过即停止扩大，只有新改动、真实失败、关键未解疑点或用户要求才增加验证。
有效且未受影响的证据直接复用，区分源码、隔离回放、真实环境、压力和长稳；昂贵方法先校准一个代表样本的输入、版本、断言和原件。必要拒错方法须能识别对应错误，不为普通小修建框架。
**必须写出的结果：验收对照**——每项指定条件的期望/实际、范围/版本与原件、PASS/FAIL/BLOCKED/NOT RUN及缺证据UNKNOWN；可保留缺陷仍如实报告，不伪报PASS。
在现有回执中逐条填：**单元/原条款 → 已执行步骤 → 期望/实际 → 原件 → 状态与缺项原因**。每个适用子选项分别给结论，不能一部分完成就整行PASS。明确区别：结果错误、明确步骤未做、已做但缺证、任务漏写/冲突、工具/资源受阻、新发现；未做不叫做错，缺证不默认叫产品bug。要求未覆盖的结论不自行补成PASS。
自动更新按约定停留原页面、无手动刷新，记录源到达与页面显示及正常周期/上限；切页、重载、截图或强制事件推动后的结果只能证明那次动作。原生标识不等于原始外部响应，API算术不等于独立余额账实；原件应来自所声明的层级。只是订正计数、算术或原件链接时就地改回执，不重执行业务。
性能给同类样本数、统计分组、窗口和失败/超时分母；不足只交观察值/未验收，不拿总样本冒充各类尾延迟通过，不把接口吞吐当交易容量。实际条件不足交回事实，不自行降门槛。
不能为绿灯改业务预期、断言或分母，也不能禁用功能、隐藏排队或无限等待来冒充成功；可凭原件纠正测试/采集错误。新成功不倒填历史缺件，保留原失败；已有原件的算术/措辞错误直接纠正，不另起采集。

## 5. 收尾并交回执行结果

MUST停止已结束或受阻单元的新增动作，按既有生命周期跟踪其已对外可见动作，核对应对象终态与配置恢复，保留原件/接续信息，清理已证本单元临时工具；独立授权项继续，预算到界或升级不省必要安全收尾。
**必须交回的执行回执**：总清单及各分支的总数/已验收/未完成分项；本轮首次执行/返工/待复审及确认验收的ID/数量；验收期望/实际和原件入口；未达原因、下一批ID、累计投入、对象终态与配置恢复。小修简记，复杂任务就地更新原清单和回执。
交回前核每条约定的步骤、实际结果和证据，补完可自主修正的已知遗漏，不等复审再往返。无新增验收如实记0，同时列新执行项及其结果，不能只交核算/映射/报告而省略总体进度。未选中的失败分支和阻塞项仍列未完成，不因本轮未触及就清零；能继续的原授权独立项直接做，后续未派发新项给出明确ID供同轮续接。
任务补充或复审要求到来时，与原约定对照：原步骤遗漏只补该段，原结果错误按反例修正，新要求/决策缺项单列增量，保留未受影响成果。若对方把未下发标准当原失败，写出原条款与差异交回待决，不争论模型能力，不自行降验收或推翻已验结果。
只按实际事实回填本批涉及的清单项，并读取同一总清单汇总总体/分支计数；不重复全库盘点或重新论证选题。批次结束、报告完成或UNKNOWN不等于总任务完成；非全局阻塞时必须衔接可执行新项。
待决摘要写共享交接的待决区（AGENTS通常是DECISION REQUIRED）：期望/实际及影响、关键原件、已试机制与累计投入、未定义选择、相关对象及可继续独立项。不必先证明完整根因或设计替代架构才交回，也不把普通实现困难抛给用户审批。
只增量记新事实，不每轮重扫、封存或复制旧证据库。报告/原件按项目既有目录规则保存，凭据不进报告/Git，按项目要求限原件权限。
提交范围遵用户和当前项目规则，代码交付不自动包括报告、方案、日志、证据、交接或Agent配置；未跟踪逐项归类，不全量暂存。项目明确“远程仅生产/长期测试及必要运行构建配置”时，其它材料仅本地，不将该项目约定套给其它项目。提交、推送和部署分别陈述；执行任务不自动包含发布或外发授权。
保护原件、备份、他人修改及既有对象。拒删或归属不明保留并说明，不换方式重试；不能用未完成清理冒充全部收尾。

# 必须停止相关动作的条件

出现任一，STOP该项试改/扩大实验，保留事实，执行步骤5并交回；其它有效授权项继续：

- 关键假设失效，或必须选未定义的业务语义、核心模型/所有者、契约、兼容性、停止/恢复规则。
- 达到累计投入预算，即使不断出现小事实；进展不自动延长授权。
- 同一失败项连续2个诊断周期无区分事实、2次实质修正仍同失败，或2次返工交回仍未达条件；停止该路径，不停止独立主线或其它分支。
- 可靠观测不可得，或准备靠加锁、等待、重试、缓存、保护开关、改阈值或扩范围代替未证原因。

这些是对应失败项的最晚边界，不要求耗满两轮。普通明确编译/装配修正不逐次计数，但工具调试消耗原预算；同一失败项跨会话、改名、换方法/脚本或拆子项均不清零，整体授权预算及预定观察窗口仍遵用户约定。
收到续接，只核新增动作、可判别结果、累计预算与停止去向是否明确。含义不变的“继续查/补全”或缺边界，交回具体缺项，不恢复已到界试改。
同一失败项到界后最多一次有新事实的明确有限续接，且遵授权总投入；再次同失败记未解决并停止该分支试改，不叠同路包。其它清单项继续；本批无可执行授权项而总清单仍有新项时，给Supervisor下一批ID，不宣称全局阻塞。只有全部未完成主线及分支均受阻，才列解除条件后暂缓总体推进。
