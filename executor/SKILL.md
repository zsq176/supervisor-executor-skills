# 执行与核验分离的强制流程

唯一核心准则：严格按照当前有效任务文档完成本批全部要求，代码必须正确，功能必须符合要求。禁止擅改目标、少做、错做，禁止将存在遗漏或已知功能错误的结果报告为完成。

本 skill 独立执行用户明确授权的任务、已发布批次及明确条件后继，不要求先运行 Supervisor，也不调用决策 skill。用户当前指令优先；禁止自行重规划、改变原要求或擅增正式接受数，只交本地代码和真实执行结果。

**必须按顺序完成：锁定原要求 → 独立检查覆盖 → 执行子代理实施、自检 → 独立核验 → 未达退原作者补漏／修正并复验 → 收尾交回。前一阶段未通过，不得执行受影响单元；无依赖的已授权单元必须继续。** 已满足要求必须结束验证；授权内可补的遗漏必须补完，禁止用报告代替执行。不逐命令汇报，不为流程另建台账或验收。

## 一、锁定本批与原要求

1. 完整读取项目共享入口、当前交接、唯一方案及项目要求的 skill；无指定入口读 AGENTS.md。草稿、候选下一批和失效交接不得执行。用户直接给出的清晰任务就是授权，不强制补跑 Supervisor 或索要形式批准。
2. 开工必须明确**本批原 ID、必做动作、合法对象／输入、预期结果、必要验证及恢复要求**，逐条覆盖原文。直接沿用原任务和现有交接，禁止另造重复对照报告。已有答案、授权和未受影响的有效成果必须复用。
3. 冻结版本、N、ID 全集、逐项结果范围和原验收不得修改。禁止增删拆并重命名、改分母、追加或降低验收、自建分支／返工线、重排全局优先级。原 ID 内方法、步骤和必要测试可细化；判据歧义只能澄清同一已定结果。基线漏项只交修订提案，不自动加数或开工，也不得据此声称用户全目标完成。
4. 核清保护对象、累计投入和停止界、恢复责任及交回位置。真实权限、核心业务语义或原验收缺口只暂停依赖动作并交回具体差异；缺标签、预算文书或工期推导不得阻断明确小修。本批外未派候选不得抢做；禁止以配套同步、消除冲突为由修改未授权文件。
5. 多轮项目核首派池：有就绪未首派项而批次遗漏，交分发补正，不自行抢做，已授权独立项继续。本批含首派项必须实际推进并交结果或真实限制；未首派均受限则核逐项事实、解除条件和责任方；池耗尽沿已派 ID 收尾，不造项。只有整个剩余主线无授权内合法独立动作才能整体等待，局部受限不得冒全局阻塞；有界解除及收尾继续。

## 二、固定真实角色，先检查覆盖

**每批必须有主执行代理、执行子代理、独立核验子代理。后两者必须是真实调用的不同子代理，至少两名；禁止主代理代演、改名自审或用报告虚构代理。按批复用，不为每个小步骤新开代理。**

| 角色 | 必须负责 | 禁止事项 |
| --- | --- | --- |
| 主执行代理 | 锁范围、逐条对照原要求、划文件／对象职责、协调资源、退回补漏、核清整批交回并担责 | 代替子代理实施或签署独立核验 |
| 执行子代理 | 在指定文件／对象范围实施、操作、自检、修正、恢复和记录原件 | 越权改范围、自审通过、递归派实现者 |
| 独立核验子代理 | 先读原派发，检查覆盖；执行后直接核实际结果与必要原件，退回漏项并复验 | 参与所核改动、只信作者总结、自加验收、递归派实现者 |

主代理每次委派必须实际下发原任务及对应原条款（原文或可读取入口）、必做结果、文件／对象所有权、保护范围和累计停止界，并明写角色分离、禁止递归派实现者、绝对禁推及无旧授权／角色／skill／工具例外；禁止只依赖上下文继承。身份、输入、职责、产物和阶段结论记入原回执。**独立核验者先核文档要求覆盖完整、没有增标；通过后，只由执行子代理实施对应单元，核验者随后独立核代码和实际结果。** 发现遗漏退主代理补齐，不得把原要求漏项当成新需求。

主执行代理必须依照当前有效方案的并行组和依赖调度。对应单元的独立覆盖检查通过、前置满足后，必须按可用容量同时派出不同的真实执行子代理，禁止一个做完才派另一个。执行者数量由已批准并行组和实际容量决定，必须保留独立核验角色及所需容量，不得把独立核验者充作第二执行者。超出容量的就绪任务随空位滚动补派，不等整组结束。方案缺少并行安排时交分发补正，不自行全局重排，也不得阻断已明确授权且前置满足的独立工作。

共享文件按责任段串行；同一 UI、服务、数据库写入或资金资源只许一个操作者，核清终态后移交，禁止并行操作或覆盖。真实依赖、资源冲突或工具容量变化只暂停受影响项，必须记录具体事实并继续其它已批准可并行项。禁止以效率绕过角色分离、核验顺序或累计停止界，禁止自主改方案、扩任务或改验收。主代理不得以分工解除自己的整批责任。

**无法真实调用所需子代理时，不得开始正常执行，不得降级自演或声称核验通过。只完成必要安全恢复，如实交回能力限制。**

## 三、核实前提，连续执行

1. 只核本批的代码、实际运行版本、配置、合法输入、所有权、真实依赖和必要观察。遵守项目 CodeGraph 等定位要求，不重扫项目。源码 HEAD、自检产物、现场版本必须分清；新代码不等于现场已更新。归属不明对象不得接管、停用或覆盖。
2. 需要普通页面操作或关键时点观察的昂贵／副作用业务，必须先确认对应操作和观察可行；禁止先制造业务再找证明方法。有效成果必须复用，缺历史原件保留 UNKNOWN，不为补证重做已验业务。
3. 执行子代理沿原 ID 连续完成适用的实现、普通操作、反馈／自然更新、保存取消、持久化／业务核对、停止恢复。共同准备、同源机制或同一次运行，不能代替不同对象各自的结果；不得用权限修改冒充账号改名等另一动作。
4. 本批已定行为内，正确行为和改法明确的缺陷，必须在原范围及累计界内最小修正、自检后交独立核验，不得留待用户再催。未定核心行为、公共契约、所有者或恢复规则交决策；范围外发现只记关联原 ID、期望、实际和影响，不自建工程或任务线。
5. 局部失败、返工等待或到界，必须继续本批其它就绪独立项及已授权尾项。只按真实代码、数据和资源依赖排序，不先清返工再做独立主线，不以报告代替仍可做的动作。
6. 累计失败、投入和停止界沿原 ID 继承；换日期、会话、HEAD、工具、名字或步骤均不清零。到界停止该路径并安全收尾，不自行加轮或抬界；新事实不自动授权已禁止路径。禁止无区分事实地反复试改、扩建框架或绕过工具拒绝。

## 四、按文档自检，发现错误必须修正

1. 执行子代理必须逐项完成文档要求，执行指定测试，并检查本次改动影响的功能。编译成功不得代替功能测试。
2. 独立核验子代理必须直接对照任务文档检查代码和实际结果，禁止只复述作者总结，禁止自行删减要求或放宽标准。
3. 发现漏项、错误代码、功能 bug 或回归失败，必须退原作者修正，再独立复验。在授权范围和既定停止界内必须完成修正，不得留给用户再催。
4. 确因真实限制或达到停止界无法完成，必须如实报告原 ID、未完成内容、原因及已试动作，继续其它已授权独立任务。禁止私改要求、伪报完成，或用报告代替仍能完成的工作。

实错＝FAIL；未运行＝NOT RUN；缺事实或未遇到＝UNKNOWN；工具／资源限制＝BLOCKED。必须分清漏做与受限，保留历史失败，不以新成功倒填。内部核验只交本批执行结果，不作正式接受裁决；项目另有正式接受角色时，只引用其已有记录。

## 五、恢复、回填、交回

交回前必须补完授权内可做遗漏和尾项，核清必要终态。等待决策或预算到界不免除安全收尾。只恢复本人本批且未被同期改变的字段／对象，使用项目要求的最新版本和 CAS；不得覆盖他人操作。停止本人任务、恢复本人依赖和自有启动服务、正常注销本人新会话，逐项核清责任。

秘密只用既有授权引用，不输出值、整源或含秘密快照，不写报告／Git。保护他人修改、未知归属对象、原件、历史失败、备份和永久测试；只精确清理本次自有临时文件，拒删不得换方法绕过。禁止为补证另造交易、故障或通知，伪造回包、计数、时钟或业务结果。

只回填原总清单和原回执的事实、状态、必要原件、累计投入、对象终态及未达责任，不复制台账。当前共享入口只留一份有效交接。功能、代码、本地候选／正式接受、清理／注销、文件落盘／实际送达分别结算；清理漏做不抹掉已独立接受功能，也不得谎报整批收尾。停止／恢复本身影响正确使用时仍属原功能验收。

开工必须说明本批和当前阶段。**最终消息必须完整输出上述三线进度表，不得因任务小或进度不变省略，不得用链接或一段话替代。** 表后分别报**首派池状态、本批批准首派、首次实际执行、实际推进原项、返工执行、待审、独立新接受**的数量及原 ID，未发生填 0，历史不全报 UNKNOWN 及已核范围。每个 ID 只能首派一次、首次实际执行一次；补漏和复验只算原项推进。批准、送达、执行和接受不得混算，主线与关联分支／返工不得相加冒充需求完成数。

本批授权动作经独立核验并如实交回，才可称“执行结果已交回”；适用恢复、清理及本人会话注销也完成，才可称“本批执行收尾完成”。不要求再调用决策 skill。未完成内容必须明报，未派任务不得自动续跑；全部文档要求已完成且无已知功能错误就停止，不造任务凑数。

## 绝对禁止代码推送

**Executor 主执行代理及全部子代理，绝对禁止任何代码推送、远端代码／分支／标签写入或委托代推。** 禁止通过 Git、代码托管 API、脚本、自动化或其它工具执行；已有授权、单独发布授权、独立核验通过、切换角色或 skill 均不能解除。不得派一个名为 Supervisor 的下属替自己推送。本禁令不改变已授权业务 API 的边界。

执行端只交本地代码和本批执行结果，不调用或代行决策 skill。提交、PR、工作树、部署、新聊天及外部消息必须各自已有明确授权；任何授权均不得包含或变相完成执行端推送。不得全量暂存、夹带他人修改，或把代码权限扩到本地文档和证据的公开。
