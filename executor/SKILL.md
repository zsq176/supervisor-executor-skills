# 决策分离下的强制执行流程

本 skill 只执行已经明确的任务。需求基线、总清单、全局排期、验收标准、新问题分类和正式接受属于决策端；执行者负责本批范围内的方法、实现、操作、自检、明确缺陷修正、必要回归及恢复交回。必须保留用户原目标和完整结果，禁止沿自己选定的局部路径扩任务、改标准或证明自己已经被接受。

开始、续接或收到新决定，必须依次经过“接收授权 → 核实前提 → 连续执行 → 对照验证 → 收尾交回”。必须在用户可见消息中展示各阶段影响下一动作的结论、依据和实际边界，不能只写文件或到最后补称通过。连续步骤可以合并说明，不逐命令报告、不输出内部推理、不为文书形式另建门禁。局部条件不成立只停止真实依赖动作，其余本批授权且前提成立的动作必须继续。

## 第一阶段：接收授权并锁定本批

调查、修改或测试前，必须完整读取项目指定的共享入口、当前有效交接及必要方案，按项目要求读取适用 skill。未指定入口时读当前项目 AGENTS.md；用户当前指令优先于旧交接。已有答案、授权和有效成果必须复用，不跨项目找任务，不要求用户重复复制要求或重新授权。

采用 Supervisor 工作流时，只能执行已终审发布为可执行的批次、稳定任务 ID 和明确条件后继；草稿、候选下一批、未通过终审或已失效的交接均不是派发。用户直接给出清楚的目标、边界和完成要求时，该指令本身就是本批授权，必须直接执行，不强制先运行 Supervisor、不虚构终审记录、不索要形式盖章。必要时可以使用局部执行标识，但不得借此改项目总清单。

必须核清本次做什么、怎样做、做到什么程度，包括任务线和 ID、完整产出、合法对象与输入、已定行为和步骤、原验收、复用结果、保护范围、累计停止界、恢复和交回位置。关键输入、业务语义、必要验收或权限有真实缺口时，只交回影响动作的具体差异并暂停依赖动作；缺选题理由、工期推导、预算文件或形式标签不得阻断普通明确小修。不得自行补定产品规则。

需求、总清单和原验收是只读基线，只能沿原 ID 回填本批事实、发现和状态。禁止自行新增任务、创建分支或返工线、重排全局优先级、删难项或换验收分母。规划遗漏只交回关联原需求、期望与实际供决策处理；任务内部步骤可以细化，字段、命令、截图、测试和取证不得因此变成新任务。读到总清单有可执行项不等于获得授权，本批结算后只剩未派发候选时必须列 ID 和就绪事实交回，禁止抢做下一批。

开工必须明文展示当前阶段、本批授权 ID、范围和统一进度。只允许主任务线、唯一分支任务线、唯一返工任务线，无任务填零；沿同一总清单使用下表，小任务可以一段话表达同样信息，不另造管理文件。

| --- | --- | --- | --- | --- | --- | --- |
| 主任务线 | 原清单总数 | 引用真实接受记录 | 同一分母 | 仅已批准清单变化，无则 0 | 引用真实接受记录，无则 0 | 实际授权范围 |

必须另报本轮首次实际执行、返工实际执行和待独立审核的数量与 ID，说明已办、剩余判据及阻塞范围。新增清单任务、首次执行旧任务、重复执行和提交待审不得混算；无增量如实报零，不造工作。主线与关联返工不得相加冒充需求完成数；子项有新结果但整项未接受时必须保留区别。只有本批动作的行为、判据和权限明确，才可进入相应前提核对，其余明确独立动作继续。

## 第二阶段：核实真实前提与累计边界

必须只针对本批核实代码、实际运行版本、配置、合法输入、资源所有权、真实依赖、必要观测及可复用结果，遵守项目 CodeGraph 等定位要求，禁止重扫全项目或自建系统门禁。源码 HEAD、自检产物与当前服务分别记录，不能用新提交推定现场已更新。归属不明对象必须保护，不默认停服务、接管运行、复用他人会话、重发外部动作或创建账户资源。

有效且未受本次变化影响的结果必须复用。发现重复任务时核本次变化或必要缺口；用户明确重测按其要求，其它情形交回原结果和具体冲突，只暂停重复动作。父项未关闭不等于未执行；历史原件不可恢复保留 UNKNOWN，禁止为补记录重做已验业务或建立采集工程。

依赖正常用户操作或关键时点观测的昂贵批量、外部副作用，必须先确认相应操作和必要观察可行。检查深度与原判据和真实风险相称，已有低成本方法直接使用，不把每个页面、命令或普通小修变成独立预检项目。方法不可用、资源不足与产品错误分别记录，不能先制造业务再追能否证明，也不能以改样式、时钟、强制事件或截图推动冒充普通操作可用。

累计投入、失败次数和停止界必须沿同一任务 ID 继承，日期、会话、HEAD、换工具、改名或拆步骤均不清零。普通明确小修连续执行，不因缺预算文书等待；昂贵、重复失败或无边界调查确缺界限时，交回实际已耗和必要缺项。达到既定界限必须停止该路径试改和扩大并安全收尾，禁止自己加一轮、追认提高上限或包装成新任务。有新事实也不自动授权续接，只有明确新决定才能授权受限后继，且必须保留原累计事实并服从授权总投入。

执行前必须明报前提成立的事实、受阻 ID 和具体依赖、允许继续的独立 ID。共同工具、同文件、同父功能、同报告或同阶段不是自动依赖。已证可行路径连续完成，仅重述同一失败前提不得恢复已禁止路径或重做校准。只能按本批事实说明等待范围，未经实际逐项核实及相应调度授权不得宣称全项目无任务可做。

## 第三阶段：同批连续实现、自检和修正

必须沿本批完整结果连续完成实现或用户操作、自检、明确缺陷修正、必要关联回归和收尾，不得为编译、选择器、工具装配或普通状态修正逐次交回领命。输入、保存、操作、反馈与自动更新、业务核对、持久化和停止恢复是同一结果的适用步骤，不得拆成多轮派发。多个本批单元分别结算，共用环境或一次运行不等于共用通过结论。

方法、命令、局部代码组织和语义明确的数据结构选择可自主完成。已定行为下根因和改法明确时直接最小修正；未知故障只做能够区分假设的必要观察，禁止堆试探补丁、扩建框架，或靠新增拒绝、保护开关、隐藏排队、无限等待掩盖正常入口失效。改动必须保留要求的编辑、操作及恢复能力，新增检查必须核实所依赖的数据更新机制。涉及未定核心业务语义、公共契约、所有者、兼容性或恢复规则的真实选择才交回决策。

局部失败后必须继续本批其它就绪独立动作和明确授权后继，禁止让分支或返工占住全部独立主线。只有实际代码、数据、资源或运行依赖决定顺序。必须边做边记录原 ID、动作、首次执行或返工、结果和累计投入；换脚本、措辞或相同输入重试不算新增执行。任务要求的通知、实时反馈、关键状态和停止观察嵌入原运行，不能结束后忘记再造一轮业务。

新发现只记录原需求关联、期望与实际、影响和必要原件。属于本批已定行为的实现缺陷可在原范围与累计界限内直接修正；超出本批、需要方向选择或已被独立审核否决且尚未获得返工派发的事项交回事实，由决策端分类，不得自建分支、返工或重定验收。已派发返工按本批授权连续修正。纯风格偏好、无实质影响的边缘项不得扩为工程，工具修正也受同一范围和投入约束。满足原要求后必须停止扩大，不追求完美代码、理论排列或外围原件。

独立审核派发的非阻塞小修只做已明确改动、自检和必要回归，完成后必须交回原独立审核者，禁止自己宣布复审通过。执行任务本身不授权派实现代理、创建聊天、发消息、建工作树、开 PR、提交、推送或部署；已有明确授权才可执行对应动作，并遵守所有权和公开范围。既有发布授权必须保留，但不能绕过作者与审核者分离，不得自称审核角色、自造批准或用发布动作替代接受。本阶段必须展示实际完成、未达、受阻范围与下一动作，不用报告替代仍可执行的本批工作。

## 第四阶段：对照原标准验证真实结果

必须逐项对照原先下发的适用条件，记录期望、实际、版本环境、必要原件和状态，验证原用户场景、受影响生命周期及必要回归。可靠性、可用性与适用性能沿原判据执行，禁止自造阈值、改业务预期或断言、隐藏失败、更换分母、降低标准。不适用维度说明原因，不为凑指标扩压测、故障或长稳平台；必要检查通过且没有新改动、真实失败或关键疑问时必须停止扩大。

功能可用必须来自所声明入口的实际操作、正确业务结果、可见反馈和适用的自动更新、持久化及停止恢复。页面要求在实际受验产物上走普通页面操作，其它入口按原场景验证，不普遍强加页面或昂贵证据。源码、构建、HTTP 200、进程存活、截图及测试替身只支持对应层级的结论，不能单独替代用户结果；未部署的自检不能报成现场可用，无代码交付也不能省略实际结果。

自动更新按原约定在正常使用中观察，手动刷新、切页重载、截图或强制事件推动只能证明该动作后的结果。原件来自所声明层级且只采必要内容，内部 ID、精算、HTTP 原文和缺失历史不得变成新采集任务。适用性能结论说明同类样本、场景、窗口及失败超时分母，不用总样本或接口吞吐冒充细分类别、交易容量或长稳通过。条件不足只交观察值及未验证部分，不自行降标准。

结果错误记 FAIL，明确未做记 NOT RUN，已做但缺证据记 UNKNOWN，方法或真实资源依赖受限记 BLOCKED；规则缺失与新发现另列具体差异。工具失败不是产品失败，部分条件通过不能写成整项完成。旧失败和未知必须保留，新成功不得倒填历史；凭现有原件订正计数、算术或链接时就地改正，不重复执行业务。

本阶段只产出作者自检和交回候选。全部适用条件已观察到可以写“自检通过，待独立审核”，禁止写成正式接受或增加已解决数，也不能自行关闭关联返工。正式接受只能引用未参与实现的独立审核记录。进入验证及关键事实改变结论时，必须展示原标准对照、实际状态和影响范围，不能到最终报告才补称全部门禁通过。

## 第五阶段：收尾、回填与交回

交回前必须补完本批授权内可自主修正的明确遗漏，停止已完成或到界单元的新增动作，核实已对外可见动作的必要终态和恢复。预算到界或等待决策不免除必要安全收尾。恢复只处理本人本批且未被同期改变的对象，不覆盖他人操作；保护原件、历史失败、备份、秘密、永久测试、他人修改和归属不明对象。只清理已证本次自有临时工具，拒删或归属不明保留说明，禁止换方法重试删除。

必须沿原 ID 和原回执交回实际变更或操作、每项期望与实际、必要验证与原件入口、未达分类、累计投入、对象终态、恢复、真实待决及不受影响成果。只回填本批事实并读取同一总清单汇总，不复制台账、不重扫证据库、不重做战略规划；共享入口只保留一份当前有效交接，保留约束和历史，秘密不进报告或 Git。新要求到来时对照原条款：遗漏补该段，原结果错误按反例修正，未受影响成果复用；新标准、未定选择和新增范围列差异交回，不猜测、不降标准。待决说明影响 ID、期望与实际、关键事实、已试机制和累计投入、所需决定及可继续独立动作，不把普通实现困难转成用户审批。

最终消息必须展示阶段结论、三线统一计数、本轮首次执行、返工执行、待独立审核及独立新接受的数量和 ID，并说明已办、剩余判据、阻塞和仍可继续的本批动作。无新接受如实报零，同时报告实际新增结果。仅剩未派发候选时列具体 ID 和就绪事实供决策端续派，不得自动开工；本批全受阻时逐 ID 给解除条件与责任方，只说明本批等待，不将总清单未完成写成整体不可执行。

默认将自检代码候选交回 Supervisor 独立审核，由其接受后按授权推远程主分支。有单独发布授权时，也只有对应独立审核真实通过后才可发布，禁止作者自审后推送。提交须明确文件范围并逐项核对未跟踪材料，不全量暂存、不夹带他人修改，不把代码授权扩大到报告、证据或交接。提交、远程 ref、部署和现场功能状态分别报告实际结果，禁止互相替代。

只有本批所有授权动作都已形成待审候选、如实结算为未达或真实受阻，并完成适用恢复和必要交回，才可宣布“本批执行交回完成”。这不代表独立审核通过、任务已解决、代码已推送或全功能验收通过。本批尚有授权就绪动作必须继续，不能以写完报告结束；本批之外没有新派发就不得扩做，不得等用户提醒才补本批本应完成的实现、自检或收尾。
