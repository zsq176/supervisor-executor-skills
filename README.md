# Supervisor / Executor Skills

Supervisor通过多个独立子代理完成需求决策、规划、审核、分发和调度，把“决定做什么”和“实现怎么做”分离。该流程用于减少开发路径过拟合、局部修补和作者自审，以有限返工和足够质量控制成本。Executor读取终审通过的执行文档，负责实现、验证和收尾。

## 新项目如何运行

主代理先用已有对话或必要的苏格拉底式提问确认用户主目标、范围及完成条件，然后依次调用真实不同的任务规划代理、任务分发代理、任务调度与审核代理；每阶段交回、落盘、展示并经阶段审通过后才能进入下游。规划必须一次覆盖主目标的全部必要需求与重要普通功能，拆成最小独立完整用户结果，形成有限原子全集并定义必要验收、依赖和批次。分发只能从该全集选择原 ID，编写步骤、必要测试、通过失败标准和停止恢复；独立调度审核覆盖、粒度、验收必要性及派发方向，主代理最后终审，不代写子代理作业。

首次整体终审永久冻结版本、主线 N、ID 全集、逐项结果范围及原验收。之后模型只能更新事实、状态、证据、依赖就绪、顺序与批次，禁止增删拆并重命名、改分母、追加或降低验收。普通原 ID 方法、步骤和测试细化无需用户再批准；歧义只能澄清既有结果及判据，不能借补细节增场景或门槛。漏项只提基线修订，不自动加数或执行；遗漏用户原要求的重要功能时也不能宣称用户全目标完成，其它原项继续。仅用户本人明确改需求或批准修订才另立新版，永久保留旧版、差异和 ID 映射并继承成果。粗大分组旧项目也仅在用户授权后首次一次校准，不能反复重规划或重验合格成果。

## 已有项目如何运行

独立代码审核代理先按冻结原验收和主要链路裁决。原标准未达或主要用户链路不通，无论简单复杂都只沿同一原 ID 返工；必要方向选择也在该返工内交回决策，不因复杂另开分支，禁止同一失败双挂。目标范围内真实且改法简单明确的功能问题，本轮直接交独立小修代理，再由未参与修改者复审；原验收未达的小修仍返工，不能先判通过。只有原标准已达且主链通畅后，非阻塞、确属原目标必要、复杂且需方向选择的问题，才进关联原 ID 的唯一有界分支。范围外完善、纯风格和理论边界不制造工作。审核通过及小修后复审通过的代码，须本轮按已有授权推送远程 main 并核 ref；不能等无依赖复杂问题全部结束，也不能只交审核报告。无代码改动仍独立审实际功能并如实说明无代码可推。

审核和处理结果落盘后，任务分发代理决定下一批从原总清单做什么，或如何针对上轮验收规则、漏测和实现缺陷修改返工交接。随后任务调度与审核代理核算三线进度、任务膨胀及最近三轮连同拟下发一轮是否偏离主目标。它只能检查和调度已有任务，不能另造任务。

多轮分发使用有限首派池。“新主线”仅指冻结原子 ID 第一次选入批准批次，实际送达另报。有合法就绪未首派原项时，本轮必须批量含至少一项，并与其它就绪主项、必要分支及返工并进；禁止主线只列计划而整轮只返工、先清返工才派独立主线。已派漏做字段、步骤、复验、补证或改名均不能再算首派，不得从大分组临时拆新项充数。

未首派原项全部具体受限时，逐项列事实、解除条件及责任方，并继续已派可做原项；池耗尽后沿原 ID 完成、复验和审结，不再要求新首派或造任务。有限仅剩项及已授权尾项连续收尾，不为凑批量留轮，待审核阶段也不是新派发轮。只有整个剩余主线无授权内合法独立动作才可整体等待，不能以未首派受限、局部 bug、工具、人手或时间冒充全局阻塞；三线仍有有界解除或收尾就继续，累计投入不清零。目标全部必要结果满足且无已知原需求缺口即结束；用户直接清晰单次任务可直接执行，不强制 Supervisor 或首派门禁。

## 怎样验收

必要验收必须在首次规划围绕主目标真实可用确定，保留重要普通功能和用户明示必验项，覆盖必要普通操作、业务正确性、可见反馈，以及适用的权限、保存取消、自然更新、停止恢复。可靠性、可用性及性能按主目标实际需要和既有要求给可观察标准，不虚构阈值，不为三维表造专项。范围外完善、罕见组合、字段穷举、历史补证及额外性能专项不强加为必验，也无需全部建永续待办；冻结后不能再借主目标删标降标。源码、构建、HTTP 200、截图和作者自报不能单独证明功能可用。

功能接受、代码交付、执行清理／本人会话注销、文件落盘和实际送达分别报告。清理漏做不能抹掉已独立证明可用的功能，责任仍须履行、未达仍单列，不能伪报整批执行收尾。若停止／恢复本身影响用户正确使用，仍是原功能必要验收。保留有效成果、历史失败和未知，不以换日期、会话、方法或 ID 清零。

## 何时允许交付

三个必需子代理依次交回后，主代理终审真实角色、落盘产物、必要验收、计数、基线冻结及目标一致性；调度与终审都核有限首派池状态。有就绪未首派却漏派、合法原项可做却空转或擅改基线，必须退回责任角色并重审受影响阶段；池耗尽或未首派均受限而已接续原项时，不因首派为0退回造项。只有终审通过才发布执行文档，用“必须、禁止、未达到不得完成”明确本次原 ID、步骤、测试、原标准和恢复，不让执行者从聊天拼需求。

子代理不可用时必须明文说明并退出，不降级为主代理代演。只能有唯一主线、唯一分支和唯一返工；支返关联原 ID、范围与投入有界、不递归、不扩主线分母或验收。每轮展示三线总数、独立接受、未解决、新增、新接受及本批批准 ID；另外分别报首派、首次实际执行、原项推进、返工执行及待审。冻结版内主线新增0，首次派发、实际执行、接受及新增不混算，三线不相加冒充需求完成数，空线填0。

Executor 依本批首派池状态实际推进首派原项或已派原项，交结果或真实阻塞；返工等待／到界继续授权独立项，不只列计划。授权不足由分发补正，执行者不扩任务、不改验收、不抢做下一批，普通方法和已授权尾项自主连续完成。自检只交候选，由未参与实现者独立接受后按已有授权发布；送达只能据用户已授权渠道，文件保存不等于执行者已收到。

## 文件与安装

[supervisor/SKILL.md](supervisor/SKILL.md)是完整强制流程，[executor/SKILL.md](executor/SKILL.md)是执行角色技能，[AGENTS-template.md](AGENTS-template.md)提供共享需求、进度、裁决与执行入口。Supervisor必须具备真实子代理工具；安装文件不等于当前宿主具有该能力。

~~~bash
# Codex
cp -r supervisor executor ~/.codex/skills/

# ZCode
cp -r supervisor executor ~/.zcode/skills/

# Claude Code（项目级）
cp -r supervisor executor <你的项目>/.claude/skills/
~~~

调用 /supervisor 开始或续接决策流程；调用 /executor 读取已发布任务并执行。沿用项目现有交接和唯一计划，不重复建立任务台账。文档与证据的公开范围遵项目约定，技能发布使用本技能仓库，不把其它项目的code-only规则套过来。
