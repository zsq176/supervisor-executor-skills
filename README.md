# Supervisor / Executor Skills

双窗口 AI Coding 工作流的两个 Skill：Supervisor 对系统成果、优先级、投入与交付负责；Executor 在已定范围内完成实现、诊断与必要验证。两个窗口通过项目根目录的 `AGENTS.md` 交接。

> The skills are written in Chinese. They work with any coding agent that supports `SKILL.md` (Claude Code, Codex CLI, ZCode, etc.); feel free to translate for your own use.

## 解决什么问题

同一个项目开两个 AI 窗口时，常见的浪费包括：

- 决策模型包办实现与普通调试，执行模型缺少自主空间；
- 目标、范围与验收不清，两个模型互相猜测或改变方向；
- 局部展示、工具或补证问题不断扩大，把整体交付拖进连续返工。

这套 Skill 的分工边界只有一条：

> **Supervisor 先决定问题是否值得现在处理，再确定范围、验收与停止条件；Executor 自主完成范围内的实现与调试。按指令执行造成的低效，不能归咎于 Executor。**

## 核心原则

- **系统成果优先**：先可用，再按实际收益改善；发现缺陷不等于必须现在修。全量审核盘点风险与覆盖，不要求修完全部发现或穷举所有排列。
- **先对清总目标与进度**：每次决策先明确最终目标/系统完成条件、当前阶段与已做成果、真实差距、下一步为什么关闭该差距、本批结束后还缺什么。答不清就不派新任务，不能把总目标换成报告或局部测试。
- **重复必须有依据**：父项 NOT RUN/FAIL 不等于从未做。重做/补证要对应“已有结果 → 具体变化或缺字段 → 原结论不足/失效 → 本次改变的决定”；没有依据直接复用或取消，不用审核、去重的新名字重复调查。
- **按业务影响排序**：错交易、错账、越权、无法停止或恢复、必要并发与延迟不成立等风险优先；有限的展示、缩放、动效或工具问题可登记保留。不能因问题难解释而提高它的权重。
- **验收先确定**：验证用户原场景与受影响生命周期。每项新增用例或补证要能改变必要判断；不随调查不断移动完成线。已知缺陷、失败、未测与缺证据如实保留，不冒充全量 PASS。
- **投入与价值相称**：昂贵调查或返工先定业务结论、产出及时间或尝试边界。用户收窄范围或时间紧时重新取舍，不继续沿旧大清单排期。
- **局部受阻，独立推进**：只串行真实的代码、数据、资源、运行状态及用户前提。产品、工具与证据问题分别结算，同报告或还没全绿不冻结其它已授权工作。
- **累计停止**：同一目标两轮诊断无区分事实、两次实质修正仍同失败，或两次返工仍未达条件，停止该项试改。预算或低价值判断可以更早停止；改名、换脚本或增加子缺陷不清零。重新判断价值后本轮最多一次有限续接，仍失败就报告未解决并退出本轮。
- **复用可靠证据**：只重验改动影响的路径；昂贵采集先校准一个有效样本。历史缺账不能靠新成功补回，明确未知后停止追补；原失败与必要原件保留。
- **交接全走文件**：`AGENTS.md` 保留六段当前目标、取舍、约束、待决项和交接，尽量约 100 行；复杂细则按需另放 `docs/plans`。不堆聊天史、旧路书或例行测试记录。

## 安装

兼容所有支持 `SKILL.md` 的 Coding Agent：

```bash
# Codex CLI
cp -r supervisor executor ~/.codex/skills/

# ZCode
cp -r supervisor executor ~/.zcode/skills/

# Claude Code（项目级）
cp -r supervisor executor <你的项目>/.claude/skills/
```

新项目可把 `AGENTS-template.md` 复制到项目根目录并重命名为 `AGENTS.md`。已有项目只合并必要结构和规则，保留现有约束与任务，不能直接覆盖。每个项目独立一份，不是全局文件。

## 使用

| 窗口 | 模型 | 启动 | 职责 |
|---|---|---|---|
| Supervisor | 擅长系统判断与取舍 | `/supervisor` | 判断价值与优先级 → 明确范围、验收、投入 → 复审并按授权交付 |
| Executor | 擅长实现与验证 | `/executor` | 读 AGENTS.md → 范围内实现与必要回归 → 结算成果；真正待决或到界时局部交回 |

典型循环：

```
你 → Supervisor（判断值得做什么，范围与停止条件落盘）
   → Executor（读 AGENTS.md，实现与验证，独立单元持续推进）
   → Supervisor（结算成果与风险，交付合格单元）
      ├ 普通范围内修正 → 同一 Executor 自主完成
      └ 待决或到界 → 重新取舍；保留问题、缩小范围或一次有限续接
```

Executor 遇到业务语义、所有者、公共契约、兼容性、显式 Scope 或验收条件冲突时，写入 `DECISION REQUIRED` 并暂停相关步骤，其它已授权独立工作继续。角色分工不授权新会话、提交推送或部署；这些动作遵用户与项目权限。缺证据或总体未通过不能外推为 PASS，也不能自动冻结全部工作。

项目代码仓库只提交生产代码、长期测试及必要运行/依赖/构建配置；审计文档、方案、日志、测试证据、交接和 Agent 配置仅本地。保留材料与提交材料分别判断，不把未跟踪文件全部推送。Skill 发布到用户指定的独立技能仓库。
