# Supervisor / Executor Skills

两个独立的角色 Skill：Supervisor 决定做什么，Executor 决定怎么做。同项目通过现有共享交接文档协作，默认使用项目根目录的 AGENTS.md。

> The skills are written in Chinese and can be used by coding agents that support SKILL.md.

## 分工

Supervisor 对目标拆分、优先级、真实依赖、范围、验收、累计投入与交付负责。Executor 在已定范围内调查、实现、调试、验证，并返回实际结果。按指令执行造成的错误方向和连续返工，不能归咎于 Executor。

共享文档中的目标、进度和决定可以被双方看到。看到背景不等于承担对方的职责：Executor 无需重新论证选题价值、全局差距或总工期。执行方案只承载已定任务及必要背景，不是把战略判断丢给 Executor 的讨论稿。

两个 Skill 各自规定本角色的步骤和输出，不依赖读取另一份 Skill，也不要求专属决策文件、隐藏记录或额外会话。沿用项目现有交接结构和权限，模板仅用于需要统一格式的项目。

## 固定步骤与明确结果

Supervisor 必须依次完成：

1. **核依据**：最新用户要求、共享交接、实际相关代码及 Skill 硬约束；明确目标/完成条件、来源和约束。
2. **核已做**：区分已验收、做过但未完整验收、真正未做、阻塞和保留；明确可复用结果与真实差距。
3. **做取舍**：决定本批、暂不做项、真实依赖、累计投入和停止去向；自己完成优先级与价值判断。
4. **生成并检查执行任务**：产出、对象/输入、动作/已定规则、前提/边界、验收/交付、停止/升级；缺执行条件先补决定，不让 Executor 猜。
5. **复审结算**：核实际变更与原件，给通过范围和未达条件，更新系统差距并决定交付或下一步。

每步留下必要事实和当前结论，更新既有交接即可，不为流程新增记录体系。目标盘点与取舍不是 Executor 的执行或报告事项。

Executor 必须依次完成：

1. **读任务**：明确本批行为、对象、验收、边界与停止条件。
2. **核前提**：核实际代码/版本、输入、资源归属、指定复用结果及累计投入；事实冲突局部交回。
3. **自主实现与调试**：明确改法直接实施；仅未知故障需要假设与区分观察，普通实现不强造诊断报告。
4. **必要验证**：返回指定条件的期望/实际、版本/范围与原件，不扩大为理论穷举。
5. **收尾与回执**：返回完成/未完成、原因、累计投入与对象终态；Supervisor 据此结算全局进度。

普通实现、编译、选择器、装配和范围内明确缺陷自主处理。仅真正未定的业务语义、核心模型、公共契约、兼容性、跨系统职责、范围/验收冲突或到界事项交回；局部停止只影响相关单元，独立授权工作继续。

## 防止重复和无限返工

- 父项 NOT RUN/FAIL 不等于从未做；先复用有效原结果。Supervisor 安排重做前必须明确“已有结果 → 实际变化/必要缺字段 → 原结论不足或失效 → 新结果改变的决定”。任务只交必要变化、动作和判定，不要求 Executor 重论价值。
- 先可用，再按实际业务收益改善。缩放、展示、动效、罕见组合及外围工具问题默认登记保留；遮蔽关键数据或阻断操作时按实际影响升级。全量审核不等于修完全部发现。
- 昂贵调查和返工先定累计边界。两轮诊断无区分事实、两次实质修正仍同失败，或两次返工仍未达条件，停止试改；预算或价值判断可更早停止。
- 改名、换脚本/方法、拆子项、跨会话不清零。到界后本轮最多一次明确的有限续接，且仍在用户/项目授权总投入内；再次失败结算并退出该目标本轮，不叠新包。
- 验收在执行前确定；编译、HTTP 200和存活不能代替业务结果。子集、回放或少量样本只支持相应结论，不冒充全量、真实环境或正式性能通过。
- 工具失败、产品失败与证据缺口分别结算。历史缺件不靠新成功倒填；原失败保留，未知如实报告。批次结束不等于整个任务完成。

## 安装

```bash
# Codex CLI
cp -r supervisor executor ~/.codex/skills/

# ZCode
cp -r supervisor executor ~/.zcode/skills/

# Claude Code（项目级）
cp -r supervisor executor <你的项目>/.claude/skills/
```

新项目可把 AGENTS-template.md 复制到根目录并重命名为 AGENTS.md。已有项目沿用现有共享文档与规则，合并必要约束，不覆盖已有任务，也不强制重排格式。两份 Skill 可分别安装和使用。

## 使用

| 角色 | 启动 | 职责 |
|---|---|---|
| Supervisor | /supervisor | 核依据和成果 → 自己做取舍 → 给可执行任务 → 复审结算与已授权交付 |
| Executor | /executor | 读任务、核前提 → 自主实现和验证 → 收尾并返回执行事实 |

典型循环是“Supervisor 已定任务 → Executor 实现验证 → Supervisor 复审”。普通范围内修正无需逐步回到决策；只有真正待决或累计到界才交回相关单元。

会话、资源、提交、部署与外部发送权限以用户和项目约定为准。提交范围不能从“有保留价值”推导；代码交付不自动包括方案、日志、证据、交接或 Agent 配置。项目要求远程仅生产/长期测试及必要运行构建配置时，其它材料只保留本地；其它项目的授权文档交付按其规则。Skill 发布到用户指定的技能仓库。
