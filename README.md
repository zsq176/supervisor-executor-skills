# Supervisor / Executor Skills

Supervisor通过多个独立子代理完成需求决策、规划、审核、分发和调度，把“决定做什么”和“实现怎么做”分离。该流程用于减少开发路径过拟合、局部修补和作者自审，以有限返工和足够质量控制成本。Executor读取终审通过的执行文档，负责实现、验证和收尾。

## 新项目如何运行

主代理先用苏格拉底式提问与用户明确初始需求，直到目标可达成、任务可拆分、结果可判定，然后落盘冻结主线目标及主要矛盾。之后必须依次调用任务规划代理、任务分发代理、任务调度与审核代理；每阶段先交回、落盘并检查，通过后才可启动下一阶段。规划覆盖全部需求并按工作量/依赖分批，避免把尾项人为留成单任务新轮；已授权尾项连续收尾。分发写明开发步骤及可靠性/可用性/性能测试验收，调度审核只核任务量与主目标一致性，不产生新任务。

## 已有项目如何运行

独立代码审核代理先按原验收标准和主要链路裁决。不达标直接记入唯一返工线；已达标后的非阻塞明确小问题交独立小修代理，随后由未参与修改的审核者复审；非阻塞方向性问题只在服务原主目标时进入唯一分支线。审核通过及小修后复审通过的代码按授权推送远程main并核ref，不能只交审核报告。

审核和处理结果落盘后，任务分发代理决定下一批从原总清单做什么，或如何针对上轮验收规则、漏测和实现缺陷修改返工交接。随后任务调度与审核代理核算三线进度、任务膨胀及最近三轮连同拟下发一轮是否偏离主目标。它只能检查和调度已有任务，不能另造任务。

新项目和已有项目的多轮分发共用硬门禁：每轮必须批量派发至少一个固定原总清单中此前未开展的真实主线用户结果，与其它就绪原主线、分支和返工同批推进。已有批次内尚未做的原功能也可计，不必增加总 ID 或分母；重复失败、补证、改名、返工兼挂主线或拆字段、命令、截图、测试不算。禁止无全局阻塞只派一个任务、只派返工或分支、先清返工才发独立主线，也不得为数量造范围外任务。

唯一允许暂停新主线派发的是不可绕过且覆盖全部待推进主线的真实全局阻塞，须逐项核实整个剩余主线，证明无合法独立路径并给出证据、解除条件和责任方。局部 bug、某平台资源不足、共享文件或工具、只有一位 Executor、编译等待、选题未定、旧缺原件、繁忙、人少、时间不足或只剩返工均不自动豁免。全局阻塞仍须派发有界解除工作和原已授权独立项，累计投入不清零。目标确已完成就结项；用户直接给出的清晰单次小任务可直接执行，不强制先跑 Supervisor。

## 何时允许交付

三个必需子代理依次交回，主代理终审其产物、独立角色、测试验收、计数和目标一致性；调度审核与主代理终审都必须核验上述批量新主线门禁。无全局阻塞证明却无新的主线结果，必须当场退回任务分发代理重排，不能警告后放行。不符合其它规则就退回原责任角色重写，并重新检查受影响的后续阶段。只有终审通过才发布执行文档。执行文档只回答本次做什么、怎样做、做到什么程度，用“必须、禁止、未达到不得完成”限定执行边界，不把审核争论和历史证据塞给执行模型。

子代理不可用时必须明文说明并退出，不降级为主代理代演。只能有一条主任务线、一条分支任务线和一条返工任务线；每轮向用户展示决策结果、各线总任务数、已解决数、本轮新增数和下一批ID，并独立明报“本轮新选／新推进主线数及原 ID、原未做结果”，不能与总清单新增或返工数混算。已有清单中选下一批不增加总数，没有任务的线填0。

Executor 必须在本批授权内实际启动推进所列新主线，交回实际结果或真实阻塞，不能只列计划而整轮只做返工。返工等待或到界时继续已授权独立项；授权不足由分发补正，Executor 不得自行扩任务、篡改验收或抢做未派发结果。自检只交候选，仍由未参与实现的审核者独立接受，再按已有授权发布。

## 文件与安装

[supervisor/SKILL.md](supervisor/SKILL.md)是完整强制流程，[executor/SKILL.md](executor/SKILL.md)是执行角色技能，[AGENTS-template.md](AGENTS-template.md)提供共享需求、进度、裁决与执行入口。Supervisor必须具备真实子代理工具；安装文件不等于当前宿主具有该能力。

~~~bash
# Codex
cp -r supervisor executor ~/.codex/skills/

# ZCode
cp -r supervisor executor ~/.zcode/skills/

# Claude Code（项目级）
cp -r supervisor executor <你的项目>/.claude/skills/
~~~

调用 /supervisor 开始或续接决策流程；调用 /executor 读取已发布任务并执行。沿用项目现有交接和唯一计划，不重复建立任务台账。文档与证据的公开范围遵项目约定，技能发布使用本技能仓库，不把其它项目的code-only规则套过来。
