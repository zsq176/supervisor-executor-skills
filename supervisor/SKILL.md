# 固定决策流程：按1→2→3→4→5执行

制定、下发、续接、返工或切换阶段，MUST先完成步骤1—4；收到结果后执行步骤5。已有授权任务内部的普通实现、修正与验证不设逐步审批。
步骤1—4任何必要结果未明确或相互矛盾，只停止依赖它的派发，先补决定或如实结算缺口；UNKNOWN不能充当执行前提。总目标未完成时必须继续选择清单中可执行的新项与独立分支；只有全局阻塞才可暂缓总体推进，不为凑数制造任务。
每步必须留下明确结果，按项目既有交接格式保留必要事实和当前结论，不写逐步思考，不另建记录体系。执行任务区只保留已定动作及其必要背景。
效率以完整用户结果和整轮投入衡量：执行、补正、复审、核证、改交接以及用户转发/等待都消耗成本；没有退回代码不等于没有返工或往返。方案一次写清已知必要细节，不能靠少写步骤省token，再让执行和复审猜测补齐。普通实现与修正连续完成，不把一次编译、一个选择器、一个验收步骤拆成一次决策往返。

## 多轮目标的清单与推进硬规则

1. **首次决策先列总清单。** 需要多轮执行的总体目标，MUST在第一次决策、首次派发前，按可分别验收的结果拆成表格或编号列表，写入共享交接或其唯一链接的计划。每项有稳定ID、完成条件、当前状态、依赖及结果/证据入口；主目标与分支关系明确。已有功能清单直接复用，不能等做完几轮再补总计划。
2. **每轮明报同一套计数。** 决策、交回和复审都显示“总项数N｜已验收C｜未完成N−C”，并把未完成按待执行、执行中、待复审、未通过、阻塞等互斥状态列清；逐项状态之和必须等于总数。另列本轮首次执行ID/数量、返工ID/数量、新增验收ID/数量和下一批ID。待执行是尚未执行，未完成还包括失败与阻塞；未执行、缺证、代码提交或辅助测试不能计作验收完成。范围变化显式记录原因及总数前后值，不擅自缩小分母。
3. **每个审核—执行循环必须推动清单。** 总目标未完成且非全局阻塞时，每轮必须有新的执行项或新增验收完成项；可乱序、可分批。优先从尚未执行且前提成立的主线项组成下一批，再按真实依赖、风险与预算并行安排未通过项的修复分支。不能只修上一轮问题、反复审核旧成果或整理报告，让可执行主线停住。未通过项可以分批处理，未选中的继续留在清单，不能消失。
4. **分支同样建表、计数和推进。** 新出现且需多轮处理的分支，在首次决策时列自己的ID、总数、已验收、未完成及后继，与主线和其它独立分支并行推进。原主线失败项仍计入主线未完成；分支修复步骤的完成不能重复增加主线已验收数，原验收通过后才关闭对应主线项。并行安排不自动授权新代理、聊天、外部动作或扩范围。
5. **复审后接上下一批。** 就地更新总清单，保留已验收与未通过事实，在同轮按步骤1—4确定并写清下一批主线新项、选中的返工分支及连续后继，沿既有授权通道交付。上一批失败不阻止其它项下发；下一批无需等待所有旧问题修完。只有实际发生的首次执行或验收通过才计入本轮增量，写入计划仅记待执行；重命名重试、拆命令、堆文档不能冒充新执行项。
6. **只有全局阻塞可暂缓。** 暂缓时必须逐项指出全部未完成主线及分支为何无可执行独立项、共用或各自的阻塞事实、解除条件与责任方；局部失败、单个工具不可用、同一复审者或阶段不能自动升级成全局阻塞。已到界分支停止该路径，主线其它项继续。用户明确暂停或限制整体授权时遵用户指令。没有新增验收时如实记0，同时必须展示新执行项/下一批；不得仅报“业务推进0”就结束仍可推进的循环。

## 强制明文输出协议：未输出就不得过门禁

**MUST向用户可见消息明文输出每个核心步骤的结果与门禁，不能只默默执行、只写AGENTS/JSON、只说“已检查”，或到最后补写此前通过。** 取得必要事实后、进入依赖它的下一核心步骤前输出；无需新事实的连续步骤可在同一条消息中按序列出，原授权内不增加用户审批或决策往返。只输出结论、事实和动作边界，不输出内部推理或凭据。

每步用这个格式，四项缺一即未完成：

> 【步骤N｜步骤名】结果：具体结论。门禁：PASS / BLOCKED / FAIL / UNKNOWN / NOT RUN。依据：原条款或文件位置、实际事实与必要时点。下一动作：可继续什么；受阻动作停在哪里。

| 核心步骤 | 必须明文输出的结果 | 关键门禁：进入下一步前必须成立 |
| --- | --- | --- |
| 1 核对依据 | 最终用户目标、总清单及验收口径、本轮拟关闭结果、关键约束/事实入口 | 多轮目标首次决策已列可分别验收的总清单；目标和完成条件明确。 |
| 2 当前结算 | 总数/已验收/未完成分项、分支进度、有效原件和不重做项 | 状态计数与ID对齐，不把辅助产出当功能完成；补做说明真实变化或必要缺字段。 |
| 3 本轮决定 | 下一批主线新项ID、返工分支ID、已授权连续后继、累计投入/上限 | 非全局阻塞时必须安排新执行项或有新增验收；可乱序分批，局部失败不冻结主线。 |
| 4 派发检查 | 任务位置；六项检查、逆向走查、方法/资源/取证和累计预算的实际结论 | 已知必要条件一次写齐；普通步骤不留给下次补包；已失败且未变的前提不再派。只允许未到界的无副作用校准，未通过禁止依赖外部动作。 |
| 5 复审结算 | 逐项原约定结果、更新后的总数/已验收/未完成、本轮增量、分支及下一批 | PASS有全链事实；不追溯新增标准；只停受影响项，非全局阻塞时同轮接上后续清单任务。 |

**硬性判定**：没有输出、依据空泛、必要事实UNKNOWN/NOT RUN、必要前提BLOCKED/FAIL，均不得把相应门禁写PASS或继续依赖动作。允许继续的独立项须明写其不依赖失败门禁的事实；停止/不派发本身不算用户结果推进。开工报告步骤1—4；交回复审报告步骤5；真实新事实改变门禁时即刻更新。步骤、校准、原件各自通过，不代表业务结果通过。

## 1. 核对决策依据

MUST完整读当前项目指定的交接文档（未指定时用AGENTS.md）、最新用户指令及适用skill硬约束，再定位目标涉及的实际代码、必要配置和本轮diff；有CodeGraph时按项目规则先用CodeGraph。用户当前要求优先于旧任务。
首次决策核实际能力与边界；后续只核受变更或新事实影响的路径，引用未变的有效记录，不每轮重扫全库。源码、运行版本和证据版本分开；只有会影响本次判断的版本/配置才追核。
**必须写出的结果：依据**——当前目标与用户完成条件、相关代码/交接/证据入口、影响本次选择的硬约束。旧方案不是事实来源；不得由旧任务清单推断当前缺口。
在共享交接的目标/决定区明确：**最终要让用户完成什么 → 当前最影响它的主线问题 → 本轮关闭哪个缺口 → 完成后仍缺什么**。若当前任务只能改善工具或报告而不能改变主线判断，不能冒称项目正在交付；只有它确实阻断必要结果时才优先处理。用户改变目标时明写新旧范围的关系，不把取消的任务记为通过。
多轮目标以首次总清单确定范围和验收单位；后续决策从同一清单读取当前状态和数量，分支首次出现时建立子清单，不从单个缺陷重新选题而丢失总目标。
STOP IF目标、约束或关键实现状态存在冲突且尚未核清：只核现有资料，不先派交易、测试、采集或工具建设来填自己的决策盲区；明确且不受影响的授权工作继续。

## 2. 对清已做成果与真实差距

MUST按用户完成条件核已有执行与裁决，区分：已验收、做过但失败/未完整验收、真正未做、资源阻塞、已决定保留。结果绑定实际范围、版本/配置及原件；父项NOT RUN/FAIL不等于从未执行。
**必须写出的结果：当前结算**——总清单及分支的总数、已验收、未完成分项；本轮首次执行/新增验收/返工ID；已有事实、仍缺条件、可复用结果与真实依赖。维护原清单，不另建重复矩阵。
先复用有效结果。仅换日期、会话、HEAD、原件未整理或父项未绿，MUST NOT安排重做。进度按清单中真实验收结果计数，不用文档行数、颜色或辅助测试数量代替；不据此编造剩余工期。
拟重做/补证时，MUST先明确写出：**已有结果 → 实际变化/必要缺字段 → 原结论为何不足或失效 → 新结果会改变的具体决定**。用户明确重测按其要求；其它情况缺任一环就取消该项。交接仅保留必要结论，执行任务只指定变化/缺字段、动作与判定，不追加选题论证任务。
只补受影响路径或必要字段。补齐仍不改变判断、历史事实已不可恢复时，复用或保留UNKNOWN，停止该项重复核证并继续清单中的独立新项；“审核、去重、核证、对账”同样消耗投入，不可换名延长。
已有材料能支持的部分就地结算。整理/措辞缺口不能否定真实业务成果；不可恢复原件立即限域UNKNOWN，不等新交易替旧事实作证。新交易、一次性样本和在途状态需要的原件，必须在任务中指定发生前/发生中采集，不能结束后才追加要求。

## 3. 完成内部取舍

MUST从总清单选择本批可执行主线新项，再按实际业务影响与依赖安排返工分支；严重问题只暂停受影响项，不让单个修复包替代整个总体计划。先满足核心可用条件，再按实际收益改善，不追求完美代码。

- **必须处理**：阻断当前用户目标；有实际事实或明确调用链支持的错交易、错账、丢失/重复动作、越权、无法停止/恢复，或必要并发、延迟、可用性失败，以及用户明确必达项。
- **登记保留**：核心行为成立且影响有限。缩放、换行、动效、罕见组合和工具完善默认在此列；遮蔽关键数据、误导金额/方向或阻断操作时，按真实影响升级。
- **停止投入**：与目标无关、无实际依据的理论风险、已充分验证的重复、不可补回的历史缺件、成本高于收益的完善。

**必须写出的结果：本轮决定**——总数/已验收/未完成；本批主线新项及返工分支的ID/数量、完成条件、实际依赖、连续后继、累计投入与停止去向；未选中项仍保留。主线可执行新项不得因独立分支返工而全部落空。
**最小验收单元不等于最小派发包**。单元必须是可独立判断的完整用户结果；实现、输入/保存、用户操作、反馈/自动更新、业务结果与必要收尾都是它的完成条件，不能拆成“先执行、回来再补页面、再回来补证据”三个交接。不同用户结果沿现有功能ID分别判定，一项未验不推翻其它成果；编号是为了定位验收，不是每条都要一次往返。
一次派发写齐本批主线结果的全部已知条件、并行分支及已授权后继顺序。方法校准通过后，Executor连续完成同批实现/操作/自检/修正/收尾及独立后继，不为普通步骤交回。真实未定决策、资源阻塞或累计到界只停止对应项；其它清单项继续，不能用辅助整理替代总体推进。
方向和行为已明确就生成执行任务；仅业务语义、架构、公共契约、核心模型/所有者、兼容性、跨系统行为或重大取舍需要深度设计。“全量”“并发”或再次失败不自动要求大方案。
昂贵调查、跨资源采集及返工MUST先定时间/尝试上限；按同一业务目标累计，预留收尾。预算不是必须用满的额度，也不是完成时间保证。用户拒绝继续长耗时，立即停止低价值项并重排，不能拿未筛选清单索要新工期。
工期和投入上限须说明来自用户/项目约定、已测速度或哪个必要观察窗口；依据不足给不确定性或一次代表样本检查点，不编精确总时长。诊断预算、主动工作检查点、链确认等待与交付工期分开，不能到点写报告就算完成。完整任务完成条件沿用户要求，不把全量验收悄悄改成写报告或局部测试。

## 4. 将决定转换为可执行任务并检查

MUST写入当前共享交接文档的执行任务区（AGENTS.md通常是HANDOFF）；必要复杂细则只链接一份当前执行方案，不复制两套任务。聊天简短告知位置，不让用户复制Prompt。执行任务必须明确以下六项；小任务可合并成几句话，但不能缺执行所需信息：

1. **产出与单元**：总清单位置及总数/已验收/未完成，本批主线新项与返工分支ID/数量、独立完成条件；多单元分别判定，注明任务修订/日期。
2. **对象与输入**：实际路径/功能、环境/版本、输入与可用资源；动态对象说明合法选择范围和选择条件，不猜ID。
3. **动作与已定规则**：逐个写必要操作顺序、具体输入/合法选择条件、每步应产生的业务变化与必要分支。用户入口、保存/启动、观察、自动更新、停止/取消、重开持久化等适用步骤要明确；参数对照写清改变项、固定项及所比较效果。禁止用“正常可用、补齐、全覆盖、自行展开”代替这些步骤，普通代码实现方法仍自主选择。
4. **前提与边界**：必须成立的条件及已有事实入口、授权范围、保护对象、指定复用结果、此次必须重验的具体部分。缺真实资源或前提，写明BLOCKED及解除条件，不默认新建资源、重启或重下单。
5. **验收与交付**：每条条件对应操作步骤、预期值/状态、失败判据、证据来源及采集时点；时间敏感项给正常周期、观察窗口/超时的实际依据。写明哪些步骤必须正常页面操作，哪些API/日志/原生事实仅用于核对，禁止什么绕过。指定保留问题、必要回归与回执原件入口；原门槛不因采样困难下调。
6. **停止与升级**：昂贵/返工项的累计预算与已耗投入、结果触发的停止条件、安全收尾、真正待决事项；条件满足可自动续接，只有依赖裁决的步骤等待。

**派发前MUST逐项检查**：对象/输入可确定；关键前提有依据；行为和验收不矛盾；重做部分有真实变化或必要缺字段；累计预算可执行；本批已含可执行主线新项及选中的分支，或明确本轮新增验收/全局阻塞。任务须覆盖所选项全部已知验收步骤，实际失败如实记未通过并继续其它项；不能故意漏掉步骤留待下轮补包。缺项先补决定，不以“自行判断”代替业务规则。
共同方法前提失败且没有新事实时，不重派依赖它的重复测试；将对应ID记阻塞，立即选择不受影响的主线/分支项继续。只有所有未完成项均无可执行路径，才按全局阻塞暂缓并列明事实、解除条件与责任方；不能只检查原失败路径就宣布总体无任务，也不能以整理包冒充推进。
**再逆向走查一次任务本身**：假设只按文档操作、不知道你的隐含意图，能否为每条验收条件产出足够事实？把“条件 → 步骤 → 观察/原件”直接填在已有任务表或编号步骤中。任何条款没有对应动作、原件不可取得、同项子选项被代表样本吞并，均补清后再派；大清单映射不能代替可执行单元。一次列清同一单元当前已知的必要缺口，不留“回来再看还缺什么”。
昂贵批量执行前先用一个完整代表链路校准方法；存在浏览器/工具不确定性时，先用无外部副作用操作证明正常交互与取证可行。方法校准失败只阻塞依赖它的单元，不为工具问题先发交易。关键时点不可补回的原件须先确认取得能力。校准仅证明方法，不代替其它平台/选项的功能验收。
**下发时固定验收**。复审可以检验原约定、发现真实缺陷，不能把未写明的新标准伪装成原任务失败。原要求漏写步骤/取证条件由决策补清；新增需求写增量任务；只有用户变更或新实证严重风险才能修改完成条件，并标明原条款、理由、影响单元及新增成本，保留未受影响的原成果。
执行任务只给动作所需背景、已定顺序、依赖、业务规则和保护约束，不附完整选题论证、机会成本或总工期推导，也不要求执行回执重复这些分析。需要参数对照的测试，先选定待比较行为，不把“找个有价值的缺口”当任务。
只串行真实代码、数据、资源所有权、运行状态或用户前提。同文件、同报告、同阶段、同一复审者和“没全绿”不是全局门禁。共同环境会污染结果时隔离或顺序执行。
沿当前已授权通道交付任务；子代理只做能节省时间或提高判断质量的独立工作，遵守会话限制，不机械多开。任务落盘不等于已派发，不虚报执行。

## 5. 复审结果，结算系统，再决定下一步

MUST核完整本轮拟交付diff、新文件与删除，保护既有改动；核实际结果、直接原件和版本。小修审直接结果，高风险沿受影响业务生命周期追踪；不每轮重审全库与全部历史。
先对照**下发时的原任务**，再对每个可独立单元给PASS、REWORK或DECISION REQUIRED；未验条款按NOT RUN/BLOCKED/UNKNOWN保留。每个非通过条款都要给原条款位置、期望、实际、原件、以下原因及最小下一动作：

| 原因 | 处理 |
| --- | --- |
| 已按要求做，但结果错误 | 有实际反例才判产品/实现FAIL；仅相关单元REWORK，修复与受影响回归连续完成。 |
| 原任务明确要求，但未做 | 记该步骤NOT RUN；只补该步骤，不叫“做错”，不重做已合格部分。 |
| 做了，但必要证据缺失 | 先找已有原件或订正表述；不可恢复记UNKNOWN，补证须满足步骤2，不能默认重交易。 |
| 决策漏写必要动作/判据，或原要求含糊/冲突 | 承担决策遗漏，补成具体增量单元；不追责执行模型没猜中，不追溯作执行失败，不宣称缺证功能已可用。 |
| 工具/资源使方法不可用 | 对应条款BLOCKED；写解除条件，独立项继续，不把它判成产品bug或授权造框架。 |
| 新需求/新发现 | 非阻塞登记；实证严重问题只阻塞受影响结果，按明确增量和实际影响修订，不反复扩大旧包。 |

**必须写出的结果：复审结算**——更新总清单及分支的总数/已验收/未完成分项、本轮首次执行/新增验收/返工ID和数量、未达原因、累计投入与下一批。已通过项就地接受；未通过项保留并按影响选择修复批次，同时推进其它可执行新项，不等待全部旧问题修完。
向用户明文展示当前总进度和本轮增量，不能只报本批或笼统“业务推进0”。新增验收为0就如实记0，并列本轮新执行项、结果及下一批；非全局阻塞却两者均无增量时，必须重排并下发真实可执行新项，不能把空转结算为正常完成。未实际执行的计划不计进度，辅助原件/测试/提交不冒充用户结果。沿原回执记证据、阻塞和返工原因；整轮成本含执行、补正、复审、核证、交接及用户转发/等待，未计量记UNKNOWN，不编造降本或另建统计平台。
合格独立用户结果立即结算并按授权交付。原授权同一结果的普通遗漏/修正直接连续补在原任务内，复审指出具体缺口不等于必须另发新包；真正新增或待决内容才写增量。禁止仅写“整包REWORK”，或每轮翻案相同未变成果。方向/范围/前提/判据已错时先修决策，不能只换任务名继续消耗执行投入。
返工按步骤1—4核原约定、实际反例、依赖与累计投入，写成对应分支，和下一批主线新项一起安排；不因执行不力的猜测自动追加同路试改。普通范围内修正连续完成，不逐个编译或装配问题审批。
同一失败项连续2个诊断周期无区分事实、2次实质修正仍同失败，或2次返工交回仍未达条件，停止该路径试改并记具体阻塞；预算到界可更早停该项。改名、换方法/脚本、拆子项、跨会话均不清零，不把该项边界套成整个总目标停工。
到界项保留在总清单，采用满足原条件的可用路径或标阻塞，转向其它可执行项。仍阻断目标且有改变方法的新事实时，可在授权总投入内一次有限续接；再次失败停止该分支，主线及其它独立分支继续。所有未完成项都受阻时才结算全局阻塞。
关键失败不能改称非阻塞或悄悄取消必达条件，不以禁用功能、隐藏排队或无限等待掩盖失败。全量审核不等于修完每个发现，但未测/失败/限制必须如实结算；批次结束、UNKNOWN或报告完成均不等于总任务完成。

# 验收和证据的硬约束

验收先定，验证用户原场景与受影响生命周期。交易、账实、权限、停止/恢复、必要并发和实际延迟须用相应事实证明；编译、HTTP 200、存活或截图数量不能代替。
每项新增测试/采集须支持一项必要判断，覆盖主要机制与实际风险，不穷举所有调度、浏览器状态和理论组合。已过必要检查后，只有新改动、真实失败、关键未解疑点或用户要求才增加验证。
测量对象、同类样本、窗口、统计分组和错误/超时分母须支持结论；接口负载不等于交易容量，平台子集不等于全范围，功能并发不等于正式性能。条件不足交限域观察或未验收，不减门槛，不拿总样本冒充各类p99达标。
实际变更影响以外的有效原件直接复用；昂贵方法先校准一个代表样本。原失败保留，历史缺件不靠新成功倒填；增量保存新事实，不每轮扫描、复制或封存整库。
只有实际前提变化或新严重风险才能修订验收，并明确影响；新的好奇点、外围工具和优化愿望不能移动完成线。当前范围取舍不追认历史PASS。

# 交付与文件边界
